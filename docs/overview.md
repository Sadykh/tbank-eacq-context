# Обзор приема платежей через СБП

Система быстрых платежей (СБП) — сервис НСПК, который позволяет оплачивать покупки по QR-коду или ссылке
из мобильного приложения любого банка-участника без использования карты.

Источники:
- <https://developer.tbank.ru/eacq/api/sbp>
- <https://developer.tbank.ru/eacq/scenarios/payments/PCI_DSS/sbp/>

## Требования к подключению

- Прием платежей через СБП не работает при схеме интеграции «Маркетплейс».
- Для подключения СБП нужно быть резидентом РФ или нерезидентом с ИНН РФ.
- Расчетный счет в Т-Банке должен быть установлен в магазине как счет для возмещений.

## Особенности способа оплаты

| Характеристика | Значение |
|---|---|
| Банки-эмитенты | все банки из [списка участников НСПК](https://sbp.nspk.ru/participants?type=person) |
| Срок жизни QR/ссылки | от 1 минуты до 90 дней, по умолчанию 24 часа (`RedirectDueDate` в `Init`) |
| Минимальная сумма | 10 рублей (`Amount` = 1000 копеек) |
| Стадийность | только одностадийная оплата |
| Возвраты | частичные и полные |
| Платежи по сохраненным реквизитам | поддерживаются (привязка счета + `ChargeQr`) |
| Обозначение в реестре | `SBP` |

## Типы QR-кодов

**Динамический QR-код** — одноразовый, для одной покупки. Сумму задает магазин, покупатель сканирует код и
подтверждает оплату. Интегрируется с облачной онлайн-кассой. Создается через API: `Init` → `GetQr`.
См. [scenario-dynamic-qr.md](scenario-dynamic-qr.md).

**Статический QR-код** — многоразовый, сумму вводит покупатель. Не интегрируется с онлайн-кассой — чек нужно
формировать вручную. Создается без API: магазин с выставлением счета → личный кабинет → «Магазины» →
вкладка «Прием оплаты» → «Статический QR-код».

## Методы API

Все методы: `POST https://securepay.tinkoff.ru/v2/<Method>`, тело `application/json`, подпись `Token`.

| Метод | Обязательные параметры | Что возвращает |
|---|---|---|
| `GetQr` | `TerminalKey`, `PaymentId`, `Token` | `Data` (payload / SVG / deeplink), `RequestKey` |
| `GetQrBankList` | `TerminalKey`, `Device.Type`, `Token` | `BankList[]` |
| `AddAccountQr` | `TerminalKey`, `Description`, `Token` | `Data`, `RequestKey` |
| `GetAddAccountQrState` | `TerminalKey`, `RequestKey`, `Token` | `Status`, `AccountToken`, `BankMemberId` |
| `GetAccountQrList` | `TerminalKey`, `Token` | `AccountTokens[]` |
| `ChargeQr` | `TerminalKey`, `PaymentId`, `AccountToken`, `Token` | `Status`, `Amount` |
| `QrMembersList` | `TerminalKey`, `PaymentId`, `Token` | `Members[]` |
| `GetQrState` | `TerminalKey`, `PaymentId`, `Token` | `Status`, `QrCancelCode`, `Amount` |
| `SbpPayTest` | `TerminalKey`, `PaymentId`, `Token` | `Success`, `ErrorCode` |

## Статусы платежа, важные для СБП

| Статус | Конечный | Описание |
|---|---|---|
| `NEW` | Да | Платеж создан методом `Init` |
| `FORM_SHOWED` | Да | Платежная форма открыта у покупателя. Для автоплатежа по СБП — банк принял запрос, ожидается подтверждение от НСПК |
| `AUTHORIZING` | Нет | Для автоплатежа по СБП — банк принял запрос от НСПК на авторизацию |
| `CONFIRMED` | Да | Платеж подтвержден, деньги списаны |
| `REJECTED` | Да | Платеж отклонен (в т.ч. после трех неудачных попыток оплаты) |
| `DEADLINE_EXPIRED` | Да | Покупатель не оплатил до истечения `RedirectDueDate` |
| `ASYNC_REFUNDING` | Нет | Обработка возврата денег по QR |
| `REFUNDING` | Нет | Возврат обрабатывается |
| `PARTIAL_REFUNDED` | Да | Частичный возврат по подтвержденному платежу |
| `REFUNDED` | Да | Полный возврат по подтвержденному платежу |

## Статусы привязки счета (автоплатежи по СБП)

| Статус | Конечный | Описание |
|---|---|---|
| `NEW` | Да | Получен запрос `AddAccountQr` |
| `PROCESSING` | Нет | QR сформирован и отправлен мерчанту |
| `ACTIVE` | Да | Привязка счета успешна |
| `INACTIVE` | Да | Привязка отклонена или деактивирована |
